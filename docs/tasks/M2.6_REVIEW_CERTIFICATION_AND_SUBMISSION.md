## 6. Domain and Data Rules

- Controlled states change only through named commands.
- Use nonsequential identifiers and external-safe references; identifiers never grant authorization.
- Enforce organization, candidacy, parent, effective-date, version, and current-record coherence in database and application layers.
- Preserve issued, submitted, signed, reviewed, decided, superseded, returned, and audit evidence immutably.
- Use unique and check constraints with RESTRICT foreign keys; never cascade-delete regulated workflow history.
- Separate general, confidential, restricted identity and financial, restricted screening and medical, and security and audit data.
- Store every version, ruleset, template, policy, and evidence reference required to reproduce consequential results.
- Update docs/DATA_MODEL.md when the accepted model is incomplete for this slice.

## 7. Authorization and Field Policy

Every route, query, command, job, file operation, callback, and provider event must:

1. Derive actor, audience, account state, assurance, and correlation context server side.
2. Require exact permission and current organization, branch, team, assignment, ownership, and record scope.
3. Enforce workflow state, field classification, purpose, separation of duties, and recent authentication.
4. Re-read or lock current state at execution time.
5. Return an explicit field-filtered projection.

Candidate authority covers only the candidate's own candidate-visible record. Staff authority is never unioned into candidate responses. Administrators have technical support authority only. Auditors are read-only and assignment, purpose, date, and field bounded.

Unauthorized and nonexistent records use indistinguishable safe results where existence disclosure creates privacy risk.

## 8. Commands, Queries, and UI

- Define exact bounded input schemas and allowlisted filters.
- Resolve hierarchy, ownership, state, applicability, authority, time, and provider facts server side.
- Use purpose-specific DTOs; never serialize ORM or database objects directly.
- Controlled statuses are labels, not editable dropdowns.
- Provide loading, empty, success, stale, conflict, denied, not-found, unavailable, retry, and terminal states as applicable.
- Candidate wording is plain and actionable; internal codes, notes, deliberations, and restricted evidence never appear.
- Routes and navigation appear only when implemented and authorized; no dead links or fake future features.

## 9. Transactions, Concurrency, and Idempotency

- Business state, history, audit, and required outbox rows commit in one transaction.
- Use expected versions and database uniqueness as final concurrency defenses.
- Idempotency keys are scoped and stored with canonical request fingerprints.
- An identical retry returns the original safe outcome; a changed request with the same key is rejected.
- Provider jobs, webhooks, imports, and schedules deduplicate stable source identities.
- Concurrent decisions cannot bypass approval counts, separation, expiration, supersession, or prerequisites.
- Tests use controlled clocks and barriers, never arbitrary sleeps.

## 10. Audit and Observability

- Register stable events for every consequential create, transition, approval, denial, restricted access, issue, signature, return, correction, expiration, revocation, export, or disposal action introduced here.
- Audit uses safe IDs, codes, versions, actor and effective scope, timestamps, reasons, and correlation only when classification permits.
- Never copy secrets, tokens, unrestricted text, raw documents, full PII, medical or screening details, financial values, or provider payloads into audit or logs.
- Required audit failure rolls back the business mutation.
- Metrics use bounded low-cardinality codes and no PII or record IDs as labels.

## 11. Security and Privacy

- Minimize collection and disclosure and apply approved retention classes.
- Enforce secure sessions, CSRF and origin checks, CSP, security headers, output encoding, allowlisted redirects, request bounds, rate limits, and protected caching.
- Keep protected data out of URLs, browser history and storage, logs, traces, metric labels, analytics, errors, source maps, screenshots, videos, and CI artifacts.
- Treat provider, webhook, file, template, and imported content as untrusted.
- Use adapters and deterministic local fakes; never contact production providers during tests.
- Use synthetic data only.

## 12. Accessibility and Usability

- Meet WCAG 2.2 AA expectations for delivered screens.
- Use semantic landmarks and headings, explicit labels, keyboard operation, visible focus, error summaries, status announcements, and non-color-only meaning.
- Support 200 percent zoom and reflow, mobile touch targets, reduced motion, understandable dates and timezones, and session-timeout recovery.
- Consequential actions require clear confirmation and explain effects without exposing internal detail.
